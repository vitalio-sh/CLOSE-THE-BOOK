# Реестр прогресса Team 10

База: `outputs/platform/progress.sqlite3`. Это локальная SQLite, она исключена из Git вместе с большими результатами. Исходный код и инструкции хранятся в репозитории. Не удаляйте `outputs`: база ссылается на сохранённые файлы доказательств.

Мы отправляем организаторам CSV с распределением банковских операций по документам, категориями и исключениями. Организаторы вычисляют официальный LIVE score по скрытым ответам. Локальные SAMPLE/TRAIN оценки записываются отдельно; они помогают отбирать варианты, но не гарантируют рост LIVE.

## Что сохраняется

- Кандидат: владелец, Git tag/commit, хеши исходного кода и доказательства проверки.
- Файл результата: путь, SHA-256, фаза, отчёт проверки формата и покрытия.
- Локальная оценка: датасет/период, score и метрики, исходный отчёт; связь с кандидатом и файлом только при подтверждённом происхождении.
- Сравнение: зафиксированные версии до/после, одинаковые входы, scorer, результаты по SAMPLE и временным окнам.
- Отправка: точный файл, локальный идентификатор попытки, серверный submission ID, этап, время, официальный ответ и score.
- События и контрольные точки: история действий, очередь, наблюдения рейтинга и курсоры чатов. Ошибочные и неполные старые отчёты сохраняются как отклонённые наблюдения.

Неизвестное происхождение старого отчёта не угадывается: такой отчёт может остаться без кандидата или с датасетом `UNSPECIFIED`. Прогнозы исследователей не записываются как измеренные оценки. Число кандидатов включает исторические варианты и служебные записи сравнения, а не только готовые релизы.

## Проверка состояния

Из корня проекта:

```sh
python3 scripts/run_ledger.py status --compact
python3 scripts/run_ledger.py integrity-check
python3 scripts/check_live_status.py
python3 scripts/run_ledger.py backup --out outputs/platform/progress.backup.sqlite3
```

Последняя команда создаёт согласованную резервную копию через SQLite Backup API. Не копируйте только основной файл работающей WAL-базы вручную.

Для импорта новых локальных отчётов:

```sh
python3 scripts/run_ledger.py scan --path outputs reports docs/reviews
```

Повторный импорт одного и того же доказательства не создаёт второй результат. Разные отчёты одного CSV могут иметь разные исходные версии; эти связи сохраняются отдельно.

## Единая очередь LIVE

Координатор интегрирует изменения solver и передаёт root-чату точный tag/SHA, проверенные сравнения и полный LIVE-файл. Root отправляет каждый новый проверенный вариант с локальным улучшением без отдельного подтверждения Vitalii. Другие чаты не резервируют слоты и не загружают результат самостоятельно. FINAL запрещён для этой очереди.

Проверка очереди и прогресса чатов настроена каждые две минуты; это интервал проверки, а не обещание новой отправки каждые две минуты. Полный прогон занимает несколько минут. Новая версия отправляется после готовности файла и проверок. Повторять те же байты ради нового score не требуется.

Команда отправки и формат доказательств описаны в `docs/LIVE_SUBMISSION_WORKFLOW.md`. У загрузчика есть блокировка процесса, уникальность SHA файла в SQLite и восстановление по существующему submission ID. После неопределённого ответа сети нельзя обходить реестр или вручную резервировать ещё один слот.

Секреты читаются из окружения или `.env`; они не входят в базу, Git и публичные сводки. Дашборд получает официальный score/место отдельно и показывает локальные оценки как локальные.
